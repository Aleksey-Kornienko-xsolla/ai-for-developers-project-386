# Пользовательские сценарии

Зафиксированные пользовательские сценарии для проверки (manual + E2E). Каждый
сценарий привязан к интеграционному тесту в [`/e2e`](../e2e).

## US-1. Гость бронирует слот (happy path)

**Актор:** гость (без аутентификации).

**Предусловия:** существует хотя бы один тип события с доступными слотами
(сид: `intro-call`, `consultation`).

**Шаги:**
1. Гость открывает `/` и переходит к списку типов событий (`/event-types`).
2. Выбирает тип (например, `intro-call`) → попадает на `/booking/intro-call`.
3. В календаре выбирает день с доступными слотами.
4. Выбирает свободный слот.
5. Заполняет форму: имя и email.
6. Нажимает «Забронировать встречу».

**Ожидаемый результат:**
- Запрос `POST /api/v1/event-types/intro-call/bookings` с заголовком
  `Idempotency-Key` возвращает `201 Created` с телом `Booking`.
- Гость видит экран успеха: тип встречи, дата/время (в локальной таймзоне),
  имя гостя, сообщение «Подтверждение отправлено на <email>».
- Слот становится недоступен (статус `booked`) для последующих попыток.

**Тест:** `e2e/tests/booking-happy-path.spec.ts`

## US-2. Конфликт слота

**Актор:** гость.

**Предусловия:** слот уже забронирован (например, через API в setup-фазе теста).

**Шаги:**
1. Гость открывает `/booking/intro-call`.
2. Выбирает день и слот, который уже забронирован.
   - В UI забронированные слоты визуально помечены и `disabled`; на них нельзя
     нажать. Поэтому сценарий тестируется через API: две параллельные попытки
     забронировать один и тот же `slotId`, либо предварительное бронирование
     через API и последующая попытка через UI с этим же `slotId`.
3. Попытка бронирования через `POST /bookings` с тем же `slotId`.

**Ожидаемый результат:**
- Вторая попытка возвращает `409 Conflict` (`Slot is already booked`).
- В UI показывается сообщение «Этот слот уже занят. Пожалуйста, выберите
  другой.» и ссылка «Выбрать другой слот».
- Список слотов инвалидируется, забронированный слот отображается как занятый.

**Тест:** `e2e/tests/booking-conflict.spec.ts`

## US-3. Идемпотентный повтор брони

**Актор:** гость.

**Предусловия:** свободный слот; нестабильная сеть (эмулируется в тесте).

**Шаги:**
1. Гость заполняет форму и нажимает «Забронировать встречу».
2. Первый `POST /bookings` «падает» на клиенте (эмуляция сброса сети через
   `page.route`).
3. UI показывает состояние ошибки / предлагает повторить.
4. Гость повторяет отправку **с тем же** `Idempotency-Key` (ключ хранится в
   `useRef` на странице и переиспользуется между попытками).

**Ожидаемый результат:**
- Второй `POST /bookings` с тем же `Idempotency-Key` возвращает **`200 OK`** с
  тем же телом `Booking`, что был бы создан первой попыткой (бэкенд кэширует
  успешный результат по ключу).
- В системе создаётся **ровно одна** запись бронирования (нет дублей).
- Гость видит экран успеха с тем же `bookingId`.

**Тест:** `e2e/tests/booking-idempotency.spec.ts`

## US-4. Несуществующий тип события

**Актор:** гость.

**Шаги:**
1. Гость открывает `/booking/unknown-type` (несуществующий id).

**Ожидаемый результат:**
- `GET /api/v1/event-types/unknown-type` возвращает `404 Not Found`.
- Страница показывает `ErrorBanner` «Тип события не найден» с кнопкой
  «Повторить».

**Тест:** `e2e/tests/event-type-not-found.spec.ts`

## US-5. (опционально) Удаление типа события с бронями

**Актор:** администратор.

**Предусловия:** у типа события есть хотя бы одна бронь.

**Шаги:**
1. Админ открывает `/admin/event-types`.
2. Нажимает «Удалить» у типа, у которого есть брони, и подтверждает.

**Ожидаемый результат:**
- `DELETE /api/v1/admin/event-types/:id` возвращает `409 Conflict`
  (`Cannot delete event type with bookings`).
- Тип остаётся в списке; показывается подсказка «нельзя удалить: есть брони».

**Тест:** `e2e/tests/admin-delete-event-type.spec.ts` (опционально)

## Покрытие сценариев в CI

- Все сценарии выполняются через Playwright E2E в GitHub Actions
  (`.github/workflows/ci.yml`, job `e2e`).
- Окружение: собранный backend (`node dist/server.js` на `:8080`) + собранный
  frontend (`vite preview` на `:4173`), `VITE_USE_MOCK=false`.
- Браузер: chromium only.
